# Keenetic VPN Bot

Telegram-бот для управления политиками маршрутизации (VPN/прокси/напрямую) и
Wake-on-LAN устройств в домашней сети через API роутера Keenetic.

## Возможности

- Переключение политики маршрутизации устройства (VPN, прокси, напрямую и т.д.) —
  список политик подтягивается с роутера в реальном времени.
- Wake-on-LAN для отмеченных устройств.
- Добавление/удаление устройств (имя + MAC) через диалог с ботом.
- Мультипользовательский и мультироутерный доступ: любой пользователь Telegram
  может подключить свой роутер, введя `host` и `password`. Если несколько
  пользователей вводят одинаковые данные роутера — они получают доступ к одному
  и тому же роутеру (общее управление). Если у пользователя несколько роутеров —
  бот даёт кнопку выбора активного.
- Все команды продублированы кнопками в постоянном меню.
- Поддержка SOCKS5-прокси для доступа к Telegram API.

## Архитектура

- [telegrambot.py](telegrambot.py) — точка входа, обработчики команд/кнопок Telegram.
- [commands.py](commands.py) — обёртки над API роутера (получить политики, задать
  политику устройству, wake-on-lan, проверка кредов).
- [keenetic.py](keenetic.py) — HTTP-клиент роутера (challenge-response авторизация
  Keenetic по MD5/SHA256, HTTPS).
- [models.py](models.py) / [db.py](db.py) — схема БД (SQLAlchemy) и функции доступа к ней.
- [crypto_utils.py](crypto_utils.py) — шифрование/хеширование пароля роутера.
- [alembic/](alembic) — миграции схемы БД.

### Модель данных

- `routers` — уникальные роутеры, идентифицируются по `host` + хешу пароля.
  Пароль хранится в двух видах:
  - `password_encrypted` — обратимо зашифрован (Fernet), расшифровывается в
    памяти только когда бот реально обращается к роутеру (для challenge-response
    авторизации нужен настоящий пароль — необратимый хеш тут не подходит).
  - `password_hash` — необратимый HMAC-SHA256, нужен только чтобы понять, что
    два пользователя ввели один и тот же пароль (дедупликация роутера), сам по
    себе доступа не даёт.
- `user_routers` — связь пользователь ↔ роутер (многие-ко-многим).
- `user_state` — какой роутер сейчас выбран активным у пользователя.
- `devices` — устройства (имя, MAC, флаг wake-on-lan), привязаны к роутеру.

Отдельного вайтлиста пользователей нет — доступ к боту открыт всем, а доступ к
конкретному роутеру определяется знанием его `host`+`password`.

## Установка и запуск

```bash
./start.sh
```

Скрипт сам:
1. найдёт подходящий Python (3.10+);
2. создаст `venv` и поставит зависимости из `requirements.txt`;
3. при первом запуске скопирует `.env.example` → `.env` и попросит заполнить
   `BOT_TOKEN` и `ENCRYPTION_KEY`;
4. накатит миграции БД (`alembic upgrade head`, создаст `bot.db`);
5. запустит `telegrambot.py`.

`./start.sh --check` — прогнать все проверки без запуска бота.

### Переменные окружения (`.env`)

| Переменная        | Обязательна | Описание |
|-------------------|-------------|----------|
| `BOT_TOKEN`       | да          | Токен бота от @BotFather |
| `ENCRYPTION_KEY`  | да          | Ключ шифрования паролей роутеров в БД. Сгенерировать: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`. **Не терять и не менять** после того, как в БД появятся роутеры — иначе их пароли станет не расшифровать. |
| `USE_PROXY`       | нет (default `true`) | Ходить ли к Telegram API через SOCKS5 |
| `PROXY_HOST`      | нет (default `127.0.0.1`) | Хост SOCKS5-прокси |
| `PROXY_PORT`      | нет (default `12334`) | Порт SOCKS5-прокси |

## Команды бота

| Команда / кнопка          | Действие |
|---------------------------|----------|
| `/start` / 📋 Устройства  | Показать устройства текущего роутера |
| `/reg` / ➕ Добавить устройство | Добавить устройство (имя + MAC) |
| `/del` / 🗑 Удалить устройство  | Удалить устройство из списка |
| 🌐 Роутеры                | Выбрать активный роутер или подключить новый |
| `/auth` / 🆔 Мой ID       | Показать свой Telegram chat ID |

Первое сообщение боту (если роутеров ещё нет) — предложение прислать
`host пароль` для подключения роутера. Данные проверяются реальным запросом к
роутеру перед сохранением.

## Миграции БД

Схема управляется через Alembic:

```bash
# применить все миграции
alembic upgrade head

# после правки models.py — сгенерировать новую миграцию
alembic revision --autogenerate -m "описание изменения"
```

[migrate_from_json.py](migrate_from_json.py) — одноразовый скрипт переноса из
старого формата хранения (`alllists.json` + `ROUTER_HOST`/`ROUTER_PASSWORD` в
`.env`), использовался при переходе на БД и оставлен как референс.

## Требования к роутеру

Прошивка Keenetic с доступом по HTTPS (443) к RCI API. Проверено на
KeenOS 5.0.12. Бот отключает проверку TLS-сертификата (роутер использует
самоподписанный сертификат).
